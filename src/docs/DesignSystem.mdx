# Peerbots Design System

The Peerbots design system ensures a consistent, accessible, and friendly experience across web applications, robot controllers, visualization tools, and community sites.

---

## 1. Design Philosophy

- **Friendly & Approachable**: Soft rounded corners, generous touch targets, and clear brand colors.
- **Accessible & High-Contrast**: Form inputs, buttons, and alerts meet WCAG contrast guidelines for therapists, educators, and learners.
- **Context-Aware Surfaces**: Opaque surfaces for high-density forms and data; tactile glassmorphism surfaces for 3D/media HUD overlays.

---

## 2. Brand Palette & Color Architecture

Defined in `src/styles/theme.css`, our color tokens fall into two primary roles:

### Canonical Brand Palette
- **Peerbots Teal (`#5fc7cc`)**: Primary brand identity, marketing accents, and active focus rings.
- **Peerbots Pink (`#e96c8a`)**: Secondary brand identity, highlights, badges, and attention-drawing elements.
- **Dark Teal (`#3f8588`)**: High-contrast interactive states and text on teal tints.
- **Dark Blue (`#2e3a59`)**: Deep navy for titles, dark cards, and primary typography.
- **Olive (`#82871f`)**: Earthy tertiary accent.

### Application & Controller Tokens
- **Electric Primary (`#46d9d9`)**: High-energy button fills and active state indicators in the controller.
- **Dark Primary (`#0f766e`)**: Hover state for electric primary buttons.
- **Secondary (`#e86e8a`)**: Canonical pink secondary token.

## 4. Glassmorphism & Surface Guidelines

The `Card` component supports `variant="glass"` (`bg-white/90 backdrop-blur-xl border border-white/40 shadow-xl`).

### When to Use Glassmorphism
- **Floating 3D HUD Toolbars**: Camera controls, zoom buttons, and parameter readouts floating above WebGL / 3D canvases.
- **Media Overlays**: Controls or title cards positioned directly over images, videos, or dynamic gradient backgrounds.
- **Floating Header Navigation**: Top navigation bars over scrolling page content.

### When NOT to Use Glassmorphism
- **Standard Forms & Text**: Never use glass on flat white or gray backgrounds. The blur is invisible, contrast is reduced, and text legibility suffers. Use `variant="elevated"` or `variant="default"` for standard UI cards.
- **Data Tables & Dense Lists**: Use solid opaque cards with crisp borders.

## 5. Core Component Usage

| Need | Recommended Component | Props / Usage |
| :--- | :--- | :--- |
| **Main Action** | `<Button variant="primary">` | Main call to action on a page or modal |
| **Brand Actions** | `<Button variant="marketing-teal">` or `marketing-pink` | Marketing CTAs and brand-styled buttons |
| **Destructive Action** | `<Button variant="danger">` | Irreversible actions (Delete, Remove) |
| **Text Inputs** | `<Input>` or `<SearchInput>` | Single-line text input with optional icons/clear |
| **Surfaces & Cards** | `<Card variant="default\|elevated\|glass">` | Structural containers and content boxes |
| **Disclosures & FAQs** | `<Accordion>` or `<Collapsible>` | Collapsible sections and multi-item FAQs |
| **Loading State** | `<Spinner size="md" color="teal">` | Animated circular loader |

---

## 6. Evolving the System

This design system is a living source of truth.
- **Component Contributions**: Any new repeatable pattern must be added as a primitive in `@peerbots/core` with corresponding Storybook stories.
- **Token Consistency**: Always use CSS variables (`var(--pb-color-*)`) or Tailwind `pb:` classes rather than arbitrary hex values.
