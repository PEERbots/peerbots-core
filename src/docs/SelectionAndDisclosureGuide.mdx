# Component Selection & Taxonomy Guide

This guide helps Peerbots engineers choose the right component when building interfaces with `@peerbots/core`, clarifying our **Layout vs. Forms vs. Patterns** taxonomy, **Disclosures**, and **Selection Controls**.

---

## 1. Layout vs. Forms vs. Patterns Taxonomy

Every UI export in `@peerbots/core` belongs to one conceptual tier in Storybook while remaining re-exported from the top-level `@peerbots/core` barrel so imports never break:

- **Forms (`Forms/*`)**: Single-value or multi-value input controls and selection primitives (`Button`, `Input`, `SearchInput`, `Select`, `Switch`, `Checkbox`, `EmotionSelector`, `PeerbotsColorSelector`, `TabRadio`, `ChipGroup`, `TabSelection`).
- **Layout (`Layout/*`)**: Structural containers, surfaces, dividers, disclosures, and semantic table primitives (`Card`, `Separator`, `Collapsible`, `Accordion`, `Table.*`).
- **Patterns (`Patterns/*`)**: Multi-component domain or workflow compositions combining multiple primitives with coordinated state (`SettingsPanel`, `CopyButton`, `Stepper`, `AuthFormUI`, `PeerbotsButtonDisplay`, `ButtonView`, `TableView`, `FlowView`).

## 2. Disclosures: `Collapsible` vs. `Accordion`

Both components live under `Layout/Disclosures/*` and provide smooth expand/collapse transitions, but target distinct cardinalities:

<div className="pb:overflow-x-auto pb:my-6">
  <table className="pb:w-full pb:text-left pb:border-collapse pb:text-xs sm:pb:text-sm pb:border pb:border-gray-200">
    <thead className="pb:bg-gray-100 pb:text-gray-900">
      <tr>
        <th className="pb:p-3 pb:border-b pb:border-gray-200">Dimension</th>
        <th className="pb:p-3 pb:border-b pb:border-gray-200"><code>&lt;Collapsible&gt;</code></th>
        <th className="pb:p-3 pb:border-b pb:border-gray-200"><code>&lt;Accordion&gt;</code></th>
      </tr>
    </thead>
    <tbody className="pb:divide-y pb:divide-gray-200 pb:bg-white">
      <tr>
        <td className="pb:p-3 pb:font-semibold">Cardinality</td>
        <td className="pb:p-3"><strong>1 standalone disclosure</strong> wrapping arbitrary React <code>children</code></td>
        <td className="pb:p-3"><strong>2+ coordinated items</strong> passed via <code>items=&#123;[...]&#125;</code></td>
      </tr>
      <tr>
        <td className="pb:p-3 pb:font-semibold">Mutual Exclusivity</td>
        <td className="pb:p-3">Independent open/close state (<code>defaultOpen</code> / <code>isOpen</code>)</td>
        <td className="pb:p-3">Single-open (<code>allowMultiple=&#123;false&#125;</code>) or multi-open (<code>allowMultiple=&#123;true&#125;</code>)</td>
      </tr>
      <tr>
        <td className="pb:p-3 pb:font-semibold">Size Scale</td>
        <td className="pb:p-3"><code>size=&quot;sm&quot; | &quot;md&quot; | &quot;lg&quot;</code> (ideal for compact sidebars)</td>
        <td className="pb:p-3"><code>variant=&quot;default&quot; | &quot;bordered&quot; | &quot;flat&quot;</code></td>
      </tr>
      <tr>
        <td className="pb:p-3 pb:font-semibold">Best For</td>
        <td className="pb:p-3">&quot;Advanced Settings&quot;, debug drawers, collapsible <code>SettingsPanel</code></td>
        <td className="pb:p-3">FAQs, multi-section troubleshooting guides, help centers</td>
      </tr>
    </tbody>
  </table>
</div>
